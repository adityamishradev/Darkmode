# PDF Reader

A browser-only PDF reader built with React, Vite, Tailwind CSS, React PDF, PDF.js, and `vite-plugin-pwa`.

## Features

## Features

### PDF reader

- Open PDF files from the device or drag and drop them onto the upload area
- Accept PDF files up to 500 MB
- Multi-page PDF.js rendering with page thumbnails
- Smooth page scrolling with automatic current-page tracking
- Previous/next navigation and direct page-number navigation
- Zoom from 50% to 300%
- Fit to width and fit to page controls
- Page rotation, fullscreen, print, download, and bookmark controls
- Search text in the PDF with result highlighting
- Restore the last viewed page
- Graceful handling for invalid, damaged, or password-protected PDFs

### Reading experience

- Dark and light application themes
- Original, sepia, and night PDF reading modes
- Responsive navigation for desktop, laptop, tablet, and mobile
- Collapsible thumbnail sidebar
- Touch-friendly mobile toolbar and footer navigation
- Keyboard shortcuts for navigation, search, zoom, and fullscreen

### PWA

- Installable on supported desktop browsers, laptops, Android, and other supported browsers
- `standalone` display mode
- Dark theme and background colors
- 192px, 512px, and maskable app icons
- Auto-updating service worker generated by `vite-plugin-pwa`
- Offline application shell and static asset caching
- In-app install button using `beforeinstallprompt` where supported
- Install prompt dismissal is remembered
- Online/offline status indicator
- PDF files are deliberately excluded from service worker caching

The project invokes Vite through its installed Node entry point in `package.json`, so the scripts do not depend on a Windows `.bin` shim being present.

npm run build
npm run preview
```

The PDF.js worker is bundled by Vite from `pdfjs-dist`, so the production build does not depend on a CDN worker.

The production build also generates `manifest.webmanifest`, `sw.js`, and precache assets. The service worker caches the application shell and static assets only. User-selected PDF files are local blob/File objects and are never added to the service worker cache.

PDF processing remains completely local in the browser.

## Important limitations

- The reader renders PDF files only. PPT and PPTX files must be converted to PDF before upload.
- A 500 MB limit is enforced to protect browser memory and rendering performance.
- Very large or image-heavy PDFs can still use substantial device memory because rendering is local.
- PDF files are not persisted in localStorage or the service worker cache.

## Deployment

Deploy the contents of `dist/` to a static HTTPS host. Configure the host to serve `index.html` for application navigation routes and preserve the generated `sw.js`, `manifest.webmanifest`, icon files, and Workbox asset.

## Test the PWA

1. **Install:** run `npm run dev`, open the app in Chrome or Edge, then use the address-bar install icon or the in-app `Install App` button when it appears.
2. **Offline:** load the app once, open DevTools > Application > Service Workers, enable Offline, and refresh. The app shell should load; local PDFs must be selected again because they are intentionally not cached.
3. **Service worker:** confirm `sw.js` is registered in DevTools > Application > Service Workers. For the production path, use `npm run build` followed by `npm run preview`.
4. **Manifest:** DevTools > Application > Manifest should show `PDF Reader`, `standalone`, dark theme/background colors, and the 192px/512px icons.
5. **Android:** open the HTTPS deployment in Chrome, choose Install app / Add to Home screen, launch it from the home screen, and verify standalone mode.
6. **Desktop/laptop:** use Chrome or Edge on HTTPS or localhost, install from the address bar, and launch the installed app window.

PDF processing remains completely local in the browser.
